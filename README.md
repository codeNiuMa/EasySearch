# EasySearch

> 少一点信息流，多一点主动选择。

EasySearch 是一个低干扰的搜索起点。它跳过网站首页的热榜、推荐和信息流，让用户选择目标网站、输入关键词，然后直接进入对应的搜索结果页。

**在线使用：** [https://codeniuma.github.io/EasySearch/](https://codeniuma.github.io/EasySearch/)

## 为什么做这个项目

很多网站的首页同时承担内容推荐、广告和热点分发功能。即使只是想查一个明确的问题，也可能在真正开始搜索前被其他内容打断。

EasySearch 将过程缩短为三步：

1. 选择搜索入口；
2. 输入关键词；
3. 直接打开搜索结果。

页面不聚合搜索结果，搜索功能也不调用各网站的搜索 API。它只负责安全编码关键词并生成目标搜索地址；天气是独立的可选组件，仅在用户设置地点后请求公开天气服务。

## 主要功能

- 桌面端采用全宽左右分栏：左侧入口库靠近页面左缘并独立滚动，搜索区在右侧剩余空间中居中；
- 移动端自动切换为“先搜索、后选择入口”的纵向布局；
- 内置 19 个通用、知识、开发、社区、视频、生活和地图入口；
- 支持分类筛选以及 `/`、`Alt + 1～9`、`Enter` 快捷键；
- 优先显示来源网站的官方图标，加载失败时回退为字母标记；
- 支持添加、删除自定义搜索入口；
- 自动记住主题、最后选择的入口和自定义配置；
- 提供浅色与深色主题，并适配桌面、平板和手机；
- 显示完整公历日期、星期与农历日期，无需外部日期接口；
- 在日期旁显示当前天气，支持城市搜索或由用户主动授权浏览器定位；
- 提供统一的组件设置，可分别显示或隐藏天气、专注说明、本地保存提示和快捷键提示；
- 支持 WebMCP 助手读取入口列表并预填搜索内容，但不会自动提交。

## 天气与组件设置

点击页面右上角的设置按钮，可以按需要显示或隐藏页面组件。设置会即时生效，并只保存在当前浏览器的 `localStorage` 中。

目前可以控制以下组件：

| 组件 | 默认状态 | 说明 |
| --- | --- | --- |
| 天气 | 显示 | 位于日期旁，展示天气、气温、体感温度和地点 |
| 专注说明 | 显示 | 说明 EasySearch 的低干扰设计目的 |
| 本地保存提示 | 显示 | 提示配置仅保存在当前浏览器 |
| 快捷键提示 | 显示 | 展示搜索框、入口切换和提交快捷键 |

天气组件默认显示，但不会自动申请位置权限，也不会在未设置地点时发送天气请求。可以通过两种方式设置地点：

- 搜索城市并从候选结果中选择；
- 主动点击“使用当前位置”，再决定是否授予浏览器位置权限。

城市搜索会展示最多 5 个候选地点，避免同名城市被直接误选。设置地点后，页面会向 [Open-Meteo](https://open-meteo.com/) 请求该坐标的当前气温、体感温度与天气状况，并在本地缓存 20 分钟。关闭天气组件后，页面不会请求天气数据。

## 使用方法

1. 在左侧选择目标网站；
2. 在右侧输入要查找的内容；
3. 按 `Enter` 或点击“直达搜索”；
4. 搜索结果会在新标签页中打开。

### 快捷键

| 快捷键 | 作用 |
| --- | --- |
| `/` | 聚焦搜索框 |
| `Alt + 1～9` | 切换前 9 个搜索入口 |
| `Enter` | 使用当前入口搜索 |

## 自定义入口

点击“添加自定义入口”，填写名称和搜索地址模板。模板必须使用 `{query}` 标记关键词所在位置，例如：

```text
https://developer.mozilla.org/zh-CN/search?q={query}
```

搜索 `CSS Grid` 时，EasySearch 会将关键词编码后替换 `{query}`，再打开生成的地址。

- 点击右上角关闭按钮、点击“取消”或按 `Esc`，都会直接退出且不保存内容；
- 保存后的自定义入口只存在当前浏览器中；
- 清理站点数据、更换浏览器或设备后，需要重新添加。

## 隐私与网络请求

EasySearch 的交互逻辑全部在浏览器中运行：

- 不包含统计、广告或用户追踪代码；
- 不需要账号、数据库或后端服务；
- 不向 EasySearch 服务器上传搜索词；
- 主题、入口和自定义配置仅保存在浏览器 `localStorage` 中；
- 组件显示偏好、天气地点和短期天气缓存仅保存在浏览器 `localStorage` 中；
- 品牌图标直接来自对应网站或其官方静态资源域名，不经过第三方图标代理；
- 图标请求不包含搜索词，并使用 `no-referrer`；
- 只有用户启用天气并设置地点后，浏览器才会向 Open-Meteo 发送地点坐标；浏览器定位只会在用户主动点击并授权后使用；
- 只有提交搜索后，浏览器才会把关键词发送给所选网站。

页面可能产生的网络请求如下：

| 请求目标 | 触发条件 | 包含的信息 |
| --- | --- | --- |
| 搜索入口官方网站 | 浏览器加载入口图标 | 图标请求，不包含搜索词，并使用 `no-referrer` |
| Open-Meteo 城市接口 | 用户在设置中查找城市 | 用户输入的城市名称 |
| Open-Meteo 天气接口 | 天气组件开启且已经设置地点 | 所选地点的经纬度 |
| 所选搜索网站 | 用户主动提交搜索 | 编码后的搜索关键词 |

### 浏览器本地数据

| 本地存储项 | 用途 |
| --- | --- |
| `easysearch.theme` | 浅色或深色主题 |
| `easysearch.selected-engine` | 最后选择的搜索入口 |
| `easysearch.custom-engines` | 用户添加的自定义入口 |
| `easysearch.widgets` | 各组件的显示或隐藏状态 |
| `easysearch.weather-location` | 用户选择的天气地点与坐标 |
| `easysearch.weather-cache` | 最长使用 20 分钟的天气缓存 |

清理该站点的浏览器数据即可移除以上所有配置。EasySearch 不会在服务器端保存这些信息。

## 项目结构

```text
EasySearch/
├── dist/
│   ├── index.html       # 页面结构与元信息
│   ├── styles.css       # 双栏布局、响应式样式与主题
│   └── app.js           # 搜索、天气、组件设置、本地配置与 WebMCP
├── .github/workflows/
│   └── pages.yml        # GitHub Pages 自动部署
├── README.md            # 项目说明
├── sousuo.py            # 旧版 Python 桌面应用
├── engine_config.json   # 旧版搜索入口配置
├── add_engine.py        # 旧版入口维护脚本
├── jsonsort.py          # 旧版配置排序脚本
└── test.py              # 旧版测试脚本
```

网页版本没有构建步骤，也没有 npm 或 Python 运行时依赖。`dist/` 中的文件就是完整的静态网站。

## 本地运行

可以直接用浏览器打开 `dist/index.html`，也可以让任意静态文件服务器将站点根目录指向 `dist/`。

修改 JavaScript 后，可执行语法检查：

```powershell
node --check .\dist\app.js
```

## 修改内置入口

内置入口位于 `dist/app.js` 顶部的 `DEFAULT_ENGINES` 数组中：

```js
{
  id: "example",
  name: "Example",
  mark: "E",
  category: "通用",
  color: "#2457d6",
  icon: "https://example.com/favicon.ico",
  template: "https://example.com/search?q={query}"
}
```

字段说明：

- `id`：稳定且唯一的英文标识；
- `name`：页面显示名称；
- `mark`：图标不可用时显示的字母或单字；
- `category`：入口所属分类；
- `color`：字母回退标记的背景色；
- `icon`：官方网站图标地址；
- `template`：包含 `{query}` 的搜索地址模板。

## 扩展页面组件

组件设置使用统一的 `data-widget` 标识进行管理。新增可隐藏组件时，需要同步完成三处配置：

1. 在页面组件根元素上添加 `data-widget="组件标识"`；
2. 在设置面板添加带有 `data-widget-toggle="组件标识"` 的复选框；
3. 在 `dist/app.js` 的 `DEFAULT_WIDGETS` 中声明该组件的默认显示状态。

组件偏好会合并默认值后写入 `easysearch.widgets`。因此后续版本增加新组件时，旧用户不需要清理已有配置，也能获得新组件定义的默认状态。

## GitHub Pages 部署

每次向 `main` 分支推送提交后，`.github/workflows/pages.yml` 会自动发布 `dist/`。

仓库需要在 **Settings → Pages → Build and deployment** 中使用 **GitHub Actions** 作为发布来源。

## 项目沿革

EasySearch 最初是一个用于学习 Python 和 CustomTkinter 的桌面小工具。仓库根目录中的 Python 文件保留为演进记录，网页版本已经不再依赖这些文件。
